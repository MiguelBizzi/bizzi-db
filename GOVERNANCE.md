# Governance

Bizzi DB is a small project, and its governance is deliberately light.

## Model

The project follows a benevolent-dictator model. Miguel Bizzi ([@MiguelBizzi](https://github.com/MiguelBizzi)) is the maintainer and makes the final call on what is merged, what ships and what the project does and does not do. Contributors advise: the maintainer listens, explains the reasoning behind a decision, and is open to being persuaded.

## How decisions are made

- **Bug fixes and small improvements:** open a pull request. The maintainer reviews it and merges it, or says what is needed.
- **New features and behavior changes:** open an issue first and describe the problem you want to solve. The maintainer decides whether it fits the project before anyone invests in code.
- **Disagreements:** discuss them in the issue or pull request. If there is no consensus, the maintainer decides and records the reason there.
- **Releases:** the maintainer cuts every release, following [RELEASING.md](RELEASING.md).
- **Conduct and security:** handled as described in the [Code of Conduct](CODE_OF_CONDUCT.md) and [SECURITY.md](SECURITY.md).

## Becoming a maintainer

Maintainers are invited by the current maintainer after a sustained record of useful, well-tested contributions and good judgment in reviews and discussions. There is no application process. A new maintainer gets write access and is listed here.

## Changing this document

This model fits a project with one maintainer. When a second maintainer joins, we will revisit it, including how disputes are settled and how many approvals a change needs. Changes to this document go through a pull request like any other.
